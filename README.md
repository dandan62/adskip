# YouTube Ad Skipper

YouTube の**スキップ可能な広告**を、スキップボタンが出現してから **0.5〜1.0 秒のランダムな間**を置いて自動でスキップする Chrome 拡張機能。

## インストール

1. Chrome で `chrome://extensions` を開く
2. 右上の「デベロッパーモード」を ON
3. 「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選択

ファイルを編集したら、拡張機能カードの 🔄（更新）を押してから YouTube のタブを再読み込みしてください。押し忘れると古いコードが動き続けます。起動ログのバージョン表記で判別できます。

## 仕組み

スキップの実体は**シーク**です。ボタンをクリックするのではなく、広告動画の再生位置を末尾に飛ばします。

```
広告開始（#movie_player に .ad-showing が付く）
  ↓
スキップボタンの出現を待つ
  ↓ フェードイン完了（opacity >= 0.9）を確認
  ↓ 0.5〜1.0 秒のランダム遅延
広告動画の再生位置を末尾へシーク
  ↓
本編へ
```

### なぜクリックではなくシークなのか

スキップボタンの自動クリックは**動作しません**。JavaScript から生成したイベントには `isTrusted: false` という印が付き、YouTube 側がこれを見て無視するためです。この値は DOM 仕様上で偽造不可（`[LegacyUnforgeable]`）と定められており、ページのスクリプトからも拡張機能の content script からも変更できません。

v1.x ではクリックを試してから失敗時にシークへフォールバックしていましたが、クリックが成功した例は一度もなかったため v2.0.0 で廃止しました。

### なぜボタンの出現を待つのか

**これが最も重要な設計判断です。**

スキップボタンの出現は、YouTube 側が「この広告はもうスキップして良い」と認めた合図です。そこから先のシークは、ユーザーがボタンを押した場合と同じ結果にしかなりません。

逆にボタン出現前にシークすれば「スキップ不可の広告を飛ばした」ことになり、検知対象の挙動そのものになります。実際に、スキップ可否と無関係に広告を早回しする再生速度の変更（v1.2.0 で実装）は YouTube 側に検知されたため v1.4.0 で削除しました。

**ボタンの出現を待つ制約は、機能上の都合ではなく安全装置です。** 外さないでください。

### 対象の video 要素

ページ内には空の `video` 要素が存在しうるため、`readyState` と `currentTime` から実際に再生中のものを選びます。広告のメディアが未読み込み（`readyState=0`）の場合は 500ms 間隔で最大 6 秒リトライします。

## 制限事項

| 項目 | 可否 |
| --- | --- |
| スキップ可能な広告（動画パート） | ✅ スキップできる |
| **一部の広告の後に出る終了カード（約7秒）** | ❌ **スキップできない** |
| スキップ不可の広告 | ❌ 仕様上スキップしない |
| `duration` を取得できない広告 | ❌ スキップできない |

### 終了カードについて

一部の広告では、シークでスキップした後に広告主の画像・見出し・「詳細」ボタンと右上の円形タイマーからなる**終了カード**が約7秒表示されます（YouTube 内部名 `ytp-video-interstitial-buttoned-centered-layout`）。

調査の結果、これは**シーク方式の副作用**だと判明しています。

- 終了カードは広告が**最後まで再生された**時に出る。スキップボタンを手動で押した場合は出ない
- シークは「一瞬で最後まで見た」ことにする操作なので、この条件に当てはまってしまう
- 終了カードが付かない広告もある（広告主側の設定によると思われる）
- 円形タイマーは CSS アニメーションではなく、ページ内部の JavaScript が時間を数えて描画を更新している。`animationend` 等のイベントを外から送っても閉じない（v2.0.4〜2.0.5 で検証済み）
- 表示中は `video` が空のためシークもできない

終了カードを出さない方法は本物のスキップボタン操作だけです。本物のクリック（`isTrusted: true`）を送る唯一の手段は `chrome.debugger` API ですが、「Chrome はこのタブをデバッグしています」という警告バーが常時表示され、そのタブで DevTools が使えなくなるため採用していません。

それでも、何もしない（広告を最後まで見る）場合と比べれば終了カードの時間は同じで、広告の動画部分だけが短縮されます。

## ON/OFF

ツールバーのアイコンからポップアップを開き、チェックボックスで切り替え（設定は `chrome.storage.sync` に保存）。

## デバッグ

コンソールを開き、フィルタ欄に `AdSkip` と入力するとこの拡張機能のログだけが表示されます。詳細な待機ログは `console.debug` なので、見るにはログレベルで Verbose を有効にしてください。

セレクタが効かなくなった場合は [content.js](content.js) の `SKIP_SELECTORS` に追加してください。

## 構成

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | Manifest V3 定義 |
| `content.js` | 検知とスキップ本体 |
| `popup.html` / `popup.js` | ON/OFF 切り替え UI |

## 変更履歴

### 2.1.0
- **重大な不具合を修正**: 広告の終了後も `.ad-showing` が残ったまま `video` に本編が読み込まれることがあり、それを広告と誤認して**本編を末尾までシークしていた**。シーク前にページのメタデータ（`meta[itemprop="duration"]` / JSON-LD）から本編の長さを取得し、一致する場合はシークしないよう変更。本編の長さが取れない場合は 10 分を超える動画をシークしない
- 終了カード表示中はシークを試みず待機するよう変更（従来は 6 秒間無駄にリトライしていた）
- 終了カードの正体と、スキップできない理由を調査して README に記録（2.0.1〜2.0.5 は調査用ビルド）

### 2.0.0
- **スキップボタンのクリックを廃止し、シーク主体に整理**。クリックは `isTrusted` により一度も成功していなかったため。ボタンの出現は「スキップ可能になった合図」としてのみ使う
- 合成マウスイベント送出、クリック検証、再クリックのリトライを削除（約35行減）
- 待機中のログを `console.debug` に整理し、通常表示のノイズを削減

### 1.6.1
- クリック後にボタンがホバー状態のまま固定される問題を修正。`mouseout`/`mouseleave` を送出し `blur()` でフォーカスも解除

### 1.6.0
- クリック直前に対象要素を検証するログを追加（識別情報、座標、`elementFromPoint` による被覆判定など）。**結果として要素の取得は完全に正しく、原因が `isTrusted` であることが確定した**

### 1.5.0
- 広告のメディアが未読み込み（`readyState=0`）でシークに失敗する問題に対応。最大 6 秒間リトライするよう変更

### 1.4.0
- **16倍速フォールバックを削除**。再生速度の変更が YouTube 側に検知されたため

### 1.3.0
- シーク対象の `video` 要素の選び方を修正。従来は最初の `video` を使っていたため、メディア未読み込みの空要素（`duration=NaN`）を掴んで失敗することがあった

### 1.2.0
- シーク失敗時の原因をログに出力
- 16倍速・ミュートで広告を流し切るフォールバックを追加（→ 1.4.0 で削除）

### 1.1.0
- スキップボタンのフェードイン完了（`opacity >= 0.9`）を待ってからクリックするよう修正。従来は `opacity: 0.5` の段階で押していた
- `.click()` から実際のマウス操作に近いイベント列の送出に変更（→ 2.0.0 で削除）
- クリック失敗時のシークフォールバックを追加
- `live_chat` など再生プレイヤーのないフレームでの多重起動を停止

### 1.0.0
- 初版。スキップボタン出現から 0.5〜1.0 秒のランダム待機後に自動クリック
